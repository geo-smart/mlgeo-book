### Assignment: **An AI-ready dataset for your project** (due Mon Nov 2)

#### **Objective**

Turn your project's data corpus into a dataset that a model can be trained on and tested with, and show it with evidence. The assignment applies the [AI-readiness rubric of lesson 2.13](2.13_MLready_data.ipynb) to your own data: criteria A1 to A4 (analysis readiness) and B1 to B7 (AI readiness), each scored 0 (missing), 1 (present but incomplete) or 2 (another team can verify it). It builds on what you have already done: a reproducible repository and environment ([HW1](../Chapter1-GettingStarted/1.9_workbench_setup_hw1.md)), cleaning rules grounded in the physics of each column (Session 5, [2.4](2.4_dataframes_prep.ipynb)), repairs graded against known truth ([2.9](2.9_filtering_data.ipynb), [2.10](2.10_synthetic_noise.ipynb)), and data dimension and principal components ([2.12](2.12_dimensionality_reduction.ipynb)).

This is a team assignment: one repository and one submission per team.

#### **What to do**

1. **Reproducible repository and data access (A1)**
   - Work in your team's GitHub repository, with the course environment (`pixi.toml` and `pixi.lock`) and a smoke test named in the `README.md`.
   - A script or notebook (`scripts/download_data.py` or `notebooks/Download_Data.ipynb`) downloads the raw data from the provider and checks that the file is the one you recorded: size, number of records, first and last records. Raw data go in `data/raw/` and are never overwritten.
   - The `README.md` names the source, version or retrieval date, license and citation of every dataset, and says which parts, if any, are synthetic or augmented. Document any access credentials needed, without committing them.
   - If your project will later run on a large archive (for inference), give its size and where it lives.

2. **Analysis readiness (A2 to A4)**
   - A cleaning script or notebook (`scripts/clean_data.py` or `notebooks/Data_Cleaning.ipynb`) writes `data/clean/`.
   - **A2 Homogenization**: one unit system, reference frame, coordinate system and time base across the record; list instrument or processing changes and how you corrected or flagged them.
   - **A3 Quality and gaps**: report missing values, sentinel values, values below a detection limit and outliers, and the physical cause of each where you can find it. Base every cleaning rule on the physics of the column and log how many values each rule changed.
   - **A4 Structure and metadata**: store the result in a standard format (Parquet, netCDF or Zarr) and describe the dataset in a file that travels with it (`data/ai_ready/description.yml`): name, version, provenance, license, citation, sampling, variables with units and dtypes, missing-data policy, number of independent units, label source, and partition definitions.

3. **AI readiness (B1 to B6)**, in `notebooks/Prepare_AI_Ready_Data.ipynb`, one short section per criterion with evidence (a count, a figure or a table):
   - State what one data sample is, what the inputs are, and what the target is (or that there is none).
   - **B1 Diversity**: count the independent units (stations, events, regions, years, instruments), not rows.
   - **B2 Distribution**: distributions of the target or classes and of the main inputs (`notebooks/EDA.ipynb` may hold the figures); the share of the rarest class or the tail; how it compares with the population the model will face.
   - **B3 Noise**: separate instrumental noise from natural variability and give a noise level or signal-to-noise estimate.
   - **B4 Augmentation**: one physically valid transformation and one that would break the physics, with a sentence on why.
   - **B5 Labels**: who or what produced the labels and how consistent they are; with few labels, say whether unlabeled data could support self-supervised learning.
   - **B6 Dimensionality**: N, D, N/D, the size in bytes, and the variance curve of the principal components (`notebooks/Dimensionality_Reduction.ipynb`); state how many components carry 90% of the variance. A t-SNE view is optional.

4. **Partitions (B7)**
   - Store train, validation and test membership with the data (a column or an index file in `data/ai_ready/`), split by independent unit.
   - Training and validation come from the same domain; the test set lies outside it along an axis you state: statistical (distance in feature space), spatiotemporal (a held-out period or region), or physical (a different process, event size or physics). Justify the choice for your scientific question.
   - Show that preprocessing statistics (scalers, imputers, principal components) are fit on the training set only. Random splits of autocorrelated data will be marked down.

5. **Score your dataset, then check an agent's score**
   - Add to the `README.md` a table of the 11 criteria with your score (0, 1 or 2) and one line of evidence each.
   - Give an assistant that can read your repository the [rubric written for agents](https://geo-smart.github.io/mlgeo-book/slides/2026/files/ai_ready_rubric_for_agents.md) and ask it to score the dataset. Save its report in `AI_logs/`.
   - Write a half-page critique of the agent's scores: at least one score that is wrong or not supported by the evidence it quotes, and how you found out. If you find none, check the scores of 2 again; agent reviews of real repositories reliably contain at least one error.

6. **Reflection**: end the `README.md` with your answers to the [three reflection questions](../Chapter1-GettingStarted/1.8_ai_in_your_workflow.md#reflect-on-each-assignment): what you learned, what you learned from agents or chatbots, and what you would improve in this assignment.

#### **Deliverables**
- A GitHub repository with the following structure:
  ```
  - data/
    - raw/
    - clean/
    - ai_ready/
  - scripts/
    - download_data.py
    - clean_data.py
  - notebooks/
    - Download_Data.ipynb
    - Data_Cleaning.ipynb
    - Prepare_AI_Ready_Data.ipynb
    - EDA.ipynb
    - Dimensionality_Reduction.ipynb
  - README.md
  ```
- `data/ai_ready/` contains the AI-ready data, `description.yml` and the stored partitions.
- The `README.md` contains the data sources and citations, the rubric score table, an AI-use disclosure (which tools, for what, what you verified), and the reflection.
- `AI_logs/` contains the agent's scoring report; the critique is in the `README.md` or in its own file linked from it.
- Submit the link to your repository on Canvas and mark the version at the time of submission (a tag or a commit hash).

#### **Grading Criteria**
- **Reproducible repository and data access, A1 (15%)**: the environment builds, the smoke test runs, the download script retrieves and verifies the data, sources and licenses are cited.
- **Analysis readiness, A2 to A4 (25%)**: homogenization, quality and gaps with a log of every cleaning rule, standard format and `description.yml`.
- **AI readiness, B1 to B6 (30%)**: one section per criterion with evidence another team can check.
- **Partitions, B7 (15%)**: stored partitions, a stated and justified out-of-domain axis, preprocessing fit on training data only.
- **Rubric score, agent check and critique (10%)**: your score table and a critique that finds a real problem in the agent's scores.
- **Reflection (5%)**: specific answers to the three reflection questions.
