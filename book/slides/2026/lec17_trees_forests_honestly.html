This is the exercise of the last slide in a published study, with a forest. In panel (a), the red dot is threshold 0.5 and the orange dot is 0.71, which maximizes recall plus specificity minus one (Youden’s J). In panels (b, c) rows are predicted and columns observed. Moving from 0.5 to 0.71 turns 4 false alarms into correct calls and 4 caught layers into misses, so accuracy stays at 88%. A forecaster who fears missing an avalanche problem may reject the “optimal” threshold. The target came from a stability test (rutschblock) and an estimate of local danger. Compared with observed avalanche activity around Davos over five winters, 69% of 252 avalanche days and 75% of 345 non-avalanche days were classified correctly. Ask: why could a forest work with only 146 samples? We return to this in a few slides.

A decision tree asks one question at a time

Each question draws one straight line, so the tree cuts the events into boxes. A new event lands in one box and takes its most common label; to predict a number, its mean.

Read the tree aloud as a seismologist would, then point to the same numbered line on the map. Question 1: noise has no impulsive onset, so its waveform is smooth. Question 2: explosions in this catalog carry more low-frequency energy. Question 3: surface events are less impulsive than earthquakes. The tree was not told any of this; it was given two columns and limited to four boxes. Ask: what would you have asked first? Exact cuts: KurtoSig 1.40, Fquart1 3.12, KurtoSig 8.78. Macro-F1 .70 on test events with these three questions and two features. The axes are stretched so the events can be seen, and the tree does not care: only the order of values matters, so no scaling is needed, unlike logistic regression. Fquart1 is read from the feature name as the first quartile of the spectrum. Same 3,000 training events as 3.5.

How does it pick the question? It tries them all

The tree tests every feature and every cut, and keeps the question that leaves each side purest. Then it repeats inside each box, never looking back.

The bars show the source types on each side of the line, and their length is the number of events. Left: this cut barely helps, because the large group has about the same mix as before. Right: one side is almost all noise. Purity has a formula (Gini impurity, or variance for numbers), but the idea is this picture: after the question, how mixed is each group? The choice is greedy: the best question now, not the best sequence of questions. A word to keep apart: a split threshold acts on a feature, while Wednesday’s decision threshold acts on a probability.

Keep asking and the tree memorizes

Curve: all 61 features.

Left to itself, a tree draws a box around almost every training event, outliers included. It becomes perfect on those events and worse on new ones, and a small change in the data can change the whole tree.

Left and right use the same 3,000 events and the same two features. The right panel has about 890 boxes. Ask: what does a new event inside one of those slivers inherit? The label of one or two neighbors. Numbers if asked, all 61 features, macro-F1 train then test: depth 2 (4 leaves) .572, .568; depth 5 .821, .792; depth 8 .825 on test, the best; full depth (18, 290 leaves) 1.000, .800. Two features: three questions .70 on test, full tree .64. Limiting depth helps a little, but the deeper problem is variance: change a few training events and the first questions can change, along with everything below them. Ask: if one tree is unstable, what can we do with many unstable trees? Same idea as averaging noisy measurements, which only helps if their errors differ. That is the next slide.

Many trees: resample events, resample features

Each tree differs from the others in two ways:

  1. It trains on a bootstrap: events drawn with replacement. About 37% are left out
  2. Each split considers a random subset of features

The forest takes a majority vote, or the mean for numbers.

Out-of-bag score: each event is predicted only by trees that never saw it, so no test set is spent.

One tree scores .774 and 300 trees score .884; the out-of-bag estimate is .882. Beyond about 50 trees the score only wobbles by ±.003.

Breiman (2001, Machine Learning 45, 5-32) is the source. Bagging is the bootstrap plus aggregation. Random features decorrelate the trees: without them, every tree would use the same strong first split, and averaging correlated errors helps little. The 37% is (1 - 1/n)^n, which tends to 1/e. More trees do not overfit in the sense of a deeper tree: they only reduce the wobble of the average, so the cost is compute. The dashed line is logistic regression at .884. Scikit-learn’s forest averages the class probabilities of the trees; for fully grown trees that is the same as the share of votes.

With all training events the forest ties logistic regression. With 40 events it leads, AUC .908 against .875, which fits a study that trained on 146 layers.

Wednesday’s seed: why use a forest if the linear model ties it? Here are three answers. It needs less preparation. It holds up better with few samples on this dataset, though the advantage is gone by about 500 events. It captures interactions without being told; boosting takes this further, at .898. Keep this honest: one split, one dataset, and differences of a few thousandths are noise. Explosions are still the weakest class for every model. The physics did not change: blasts and shallow earthquakes overlap in these features. Boosted trees are histogram gradient boosting with default settings. Leaderboard: closes Nov 24; .898 is now a number to beat, and it was reached on the test set once. Choose your own model with cross-validation on the training set.

This is why the same drawing is useful for a second model. The curves almost overlap, so the two models rank events about equally well. When the trees disagree

For each of the 1,000 test events, count the trees voting for the winning class.

  • Above 90% of the trees: 453 events, 2% wrong
  • Below 50% of the trees: 76 events, 47% wrong

The labels are not needed to compute the agreement, so low-agreement events can go to an analyst first.

The 254 events with agreement below 70% are 1 in 4 test events and hold 85 of the 115 errors. Agreement ranks events; it is not yet a calibrated probability.

Forest of 300 trees on the four source types. Errors in the two lowest bins: 36 + 49 = 85 of 115, which are the rates times the counts in the figure: .474 x 76 and .275 x 178. In the two highest bins: 20 + 10 = 30. Disagreement among trees trained on different resamples estimates epistemic uncertainty: what the model has not learned. It does not measure noise in the measurement itself (aleatoric). Same recipe returns in lesson 4.5 as deep ensembles (Lakshminarayanan et al., 2017). Book section 3.9 runs this with bagged trees.

Part 2. For a number, each box stores a mean

Same questions, same boxes. The target is the daily change in soil moisture at Turnbull, and each box predicts the mean change of its training days (m³/m³).

Read it as a hydrologist. Little or no rain: the soil keeps drying slowly. A downpour: a large rise. Moderate rain: the same water adds less to soil that is already wet. The tree found the last idea alone, from two columns. Each dot is one training day, colored by its real change, so the spread inside a box is visible. Cuts: rain 4.55 and 21.3 mm, moisture yesterday .231 m³/m³. Training days per box: 1,500 slow drying, 64 and 58 with moderate rain, and only 8 downpours, so +.052 rests on few days. R² on the test years, 2021 to 2024: .23 for these four boxes.

A regression tree predicts in stairs

The tree keeps the question that most reduces the spread inside each group, the same idea as purity. More levels make more stairs; without a limit they follow single days; averaging many trees smooths them.

One feature, so we can draw the prediction itself. Daily maximum ground surface temperature from air temperature at Turnbull, training years 2015 to 2020. Gray: training days. Red: one tree. Green: the mean of 300 trees, which is still built of steps, only fine ones. For classes the tree lowers impurity; for numbers, the variance inside each group. Numbers if asked, mean absolute error on 2021 to 2024: one question 8.1 °C, three levels 4.5, no limit 4.5, forest 4.4. On this clean relation a full tree does little harm. How much correlation is a problem?

Soil moisture, western US. Each cell is predicted from training cells beyond a distance.

Forest biomass, central Africa. XY: coordinates. RSE: satellite and environment. Shorter distance axis.

Ploton et al. (2020), Nat. Commun. 11, 4540, Fig. 5a. doi:10.1038/s41467-020-18321-y. CC BY 4.0.

There is no fixed limit: compare your prediction distance with the field’s correlation distance. A random split gives both soil moisture forests R² .91; at 500 km they reach .01 and .85. In central Africa both fall together, so nearness was doing the work.

Correlation does not break the fit: a forest assumes nothing about independence. It breaks the test, because a random split asks about neighbors. The dashed line is the field itself: correlation .81 within 100 km, .40 at 200 to 300 km, near zero by 900 km. The forest on coordinates loses its skill at about that same pace, because nearness is all it has: .94, .75, .58, .38, .01 at 0, 100, 200, 300, 500 km. Climate: .93, .90, .90, .89, .85, then .68 at 750 and .45 at 1,000 km. So there is no universal number of kilometers: measure the correlation distance of your field and the distance from your prediction sites to your training sites, and compare. Ploton: the dashed gray line is their spatial cross-validation at .14. Both models give similar R² at every radius, so the satellite features add little beyond location. A second cost: 992 correlated cells carry less information than 992 independent samples. Methods: buffered leave-one-out on 250 random cells, 80 trees each. When spatial correlation matters

Situation A problem? What to do
Filling gaps: prediction sites as close to training as your test sites Not for the score. A random split asks the right question if samples represent the map Random folds (Wadoux et al., 2021)
Predicting a new region, beyond the correlation distance Yes. Random folds report near-neighbor skill Hold out blocks with a buffer as wide as your real distance (Roberts et al., 2017)
Longitude and latitude as features Depends on the task. They score .91 in gaps, .01 at 500 km Prefer features with a mechanism; test with a buffer
Out-of-bag score Yes on maps. It leaves neighbors in: .91 for coordinates alone Do not use it as a spatial test
Correlated features, not samples Not for predictions. Importance splits among them Read correlated features as a group
New conditions in feature space Yes, at any distance. A forest cannot leave its training range Report where the map applies (Meyer and Pebesma, 2022)

Wadoux, Heuvelink and de Bruin (2021), Ecol. Model. 457, 109692. Roberts et al. (2017), Ecography 40, 913–929. Meyer and Pebesma (2022), Nat. Commun. 13, 2208.

Leave this up and ask each team which row is theirs. The debate is real: Wadoux et al. argue that spatial folds misstate map accuracy when the sample represents the map, and that a clustered sample needs a different remedy. Roberts et al. argue for blocking when the goal is prediction beyond the sampled structure. They answer different questions, the same point as the validation ladder on Monday. Hengl et al. (2018, PeerJ 6, e5518) add distances to sampling sites as features, a further option for gap filling. The feature-space row leads to the next slide.

USCRN WA Spokane 17 SSW, 2015 to 2024. Infrared ground sensor, daily maximum. 2,301 training days, 570 hot days.

On cool days the two tie. On hot days the forest’s error doubles because every prediction is an average of training values, so its curve goes flat above 28 °C.

The test is designed: we removed hot days from training to see the behavior clearly, as 3.2 did with silica-rich rocks, where a granite received the density of an evolved andesite. Students should say the mechanism aloud: a forest cannot predict above the highest leaf mean. Not a reason to avoid forests, but a reason to ask whether your deployment leaves the training range: a warmer climate, a new volcano, a new sensor. It is a stronger limit than distance: a nearby site can still be outside the training range. The linear model is only safe here because the relation happens to be nearly straight; it would extrapolate just as confidently if the relation bent. Validation on cool days cannot tell them apart: 4.1 and 4.0.

Importance: what the forest used

Snow instability. Impurity importance of the final six features. Features correlated above r = 0.8 were removed first.

Mayer et al. (2022), Fig. 6. CC BY 4.0. ε̇ᵥ: viscous deformation rate; r_c: critical cut length; P_k: skier penetration depth.

Soil moisture. Add yesterday’s moisture again, in percent. Its credit splits .99 into .53 and .46, while the error stays at .0033 to .0034 m³/m³.

Impurity importance divides credit among correlated features. Removing correlated features first, as Mayer et al. did, or shuffling groups of features on held-out data gives a fairer reading; neither shows cause.

Impurity importance: how much a feature lowers impurity across all splits, computed on training data. Copying a feature tells us nothing new about soil, but its importance falls by half. Real features correlate in the same way: moisture at 5 and 10 cm, temperature and solar radiation. Permutation importance asks a better question: shuffle a feature in held-out data and measure the damage. Here shuffling yesterday’s moisture raises the error from .0033 to about .12 m³/m³. It too suffers with correlated features, because the model can lean on the partner: interpret such a group together. Strobl et al. (2007, BMC Bioinformatics 8, 25) measured the bias of impurity importance. Importance describes the model, not the physics: shuffling a column does not change the soil. Part 4. Best practices: training a classifier

Practice Seen in this course
1. Choose the decision and the metric before fitting Always answering “earthquake” at 5% explosions: accuracy .949, no use
2. Split first, by what samples share: event, station, time, region Oversampling before the split: F1 .995. After: .590
3. Fit a baseline and a simple model first Logistic regression ties the forest at .884
4. Keep preprocessing in a pipeline fit on training folds Logistic regression on raw features: .783
5. Start from defaults; tune by cross-validation on training data Forest defaults .881 ± .015; no setting tested beat them by more than .001
6. Treat rare classes and choose the threshold on validation data Same AUC, yet 62 or 89 explosions missed at 0.8
7. Report per-class errors and spread; open the test set once Explosions are the weakest class in every model

Best practices: training a regressor

Practice Seen in this course
1. Beat the physical baselines: climatology and persistence Error .0284 and .0042; forest .0033 m³/m³
2. Split by time or place, matching how you will predict At 500 km, R² .85 with climate and .01 with coordinates
3. Report error in units and by regime, not only R² R² .997, yet rainy-day error is 3 times the mean error
4. Noisy target: grow larger leaves Daily moisture change, R²: leaf size 1 .09; leaf size 20 .28
5. Check how many features each split sees One third instead of all (scikit-learn’s default): error .0060 against .0047
6. Test beyond the training range Hot days: error 4.1 to 7.9 °C
7. Give a range with each prediction Quantile forests, as in SoilGrids
