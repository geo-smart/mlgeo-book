# 1.9 Devoir 1 : installer votre poste de travail

🖥️ [**Diapositives du cours — Séance 02 (ven. 2 oct.)**](https://geo-smart.github.io/mlgeo-book/slides/2026/lec02_your_workbench.html)

Cette page est le devoir 1 (HW1). Elle vous guide dans l'installation des outils que vous utiliserez tout le trimestre : pixi pour les environnements, git et GitHub pour le contrôle de version, JupyterLab pour les carnets. Chaque étape se termine sur un état vérifiable, pour toujours savoir si elle a réussi avant de continuer. Comptez une à deux heures ; demandez de l'aide tôt si une étape échoue.

À la fin vous aurez : pixi et git installés, un compte GitHub, votre dépôt de cours personnel `MLGEO2026_UWNETID` (remplacez `UWNETID` par votre identifiant UW), le livre du cours fonctionnant localement, et un *commit* poussé vers votre propre dépôt.

```{note}
**Utilisateurs de Windows : lisez ceci d'abord.** L'environnement du cours (`pixi.toml`) cible actuellement macOS (Apple silicon) et Linux, pas Windows natif. Deux chemins officiels :

* **WSL2 (voie principale).** Windows Subsystem for Linux vous donne un système Ubuntu complet dans Windows. Ouvrez PowerShell en administrateur, lancez `wsl --install`, redémarrez, puis ouvrez le terminal Ubuntu ([guide d'installation de Microsoft](https://learn.microsoft.com/en-us/windows/wsl/install)). Ensuite, suivez toutes les instructions Linux de cette page dans le terminal Ubuntu. VS Code se connecte directement à WSL2 avec l'[extension WSL](https://code.visualstudio.com/docs/remote/wsl).
* **GitHub Codespaces (repli sans installation).** Si WSL2 n'est pas possible (portable bridé par votre institution, disque plein), tout se fait dans le navigateur : après l'étape 2 (compte GitHub), ouvrez le dépôt du cours sur GitHub, cliquez sur **Code → Codespaces → Create codespace**, et reprenez à l'étape 4 dans le terminal du codespace. Les comptes personnels incluent un quota mensuel gratuit.
```

## Étape 1 — Installer pixi

**macOS / Linux / WSL2**, dans un terminal :

    curl -fsSL https://pixi.sh/install.sh | sh

Sur macOS avec [Homebrew](https://brew.sh), `brew install pixi` fonctionne aussi. Après l'installation, fermez et rouvrez le terminal pour que votre shell prenne en compte le nouveau PATH.

**Vérifier :**

    pixi --version

La réussite ressemble à ceci : un numéro de version s'affiche, p. ex. `pixi 0.48.0`. Si la commande est introuvable, redémarrez le terminal ; si elle reste introuvable, l'installateur affiche la ligne à ajouter à votre profil de shell — ajoutez-la et redémarrez encore.

## Étape 2 — Installer git et créer un compte GitHub

Vérifiez si git est déjà installé :

    git --version

Sinon : sur macOS, cette commande déclenche l'installateur des Xcode Command Line Tools (acceptez) ; sur Ubuntu/WSL2, `sudo apt install git`.

Puis :

1. Créez un compte sur [github.com](https://github.com/) et configurez l'authentification à deux facteurs (voir [1.5](1.5_version_control_git.md#authentication)).
2. Dites à git qui vous êtes, avec les mêmes nom d'utilisateur et adresse que le compte GitHub :

       git config --global user.name "superseismo"
       git config --global user.email "superseismo@uw.edu"

3. Installez le [GitHub CLI](https://cli.github.com/) et authentifiez-vous :

       gh auth login

   Acceptez les valeurs par défaut (GitHub.com, HTTPS, connexion via le navigateur) et suivez les invites du navigateur.

**Vérifier :**

    git --version
    gh auth status

La réussite ressemble à ceci : git affiche une version 2.40 ou plus récente, et `gh auth status` annonce `Logged in to github.com` avec votre nom d'utilisateur.

## Étape 3 — Créer votre dépôt de cours

Créez votre dépôt de cours personnel, nommé `MLGEO2026_UWNETID` (votre identifiant en capitales, p. ex. `MLGEO2026_SUPERSEISMO`). Ce dépôt accueille vos devoirs et votre projet pour le trimestre. Créez-le **une seule fois**, avec une commande :

    gh repo create MLGEO2026_UWNETID --public --add-readme --license mit --clone

Cela crée le dépôt sur GitHub avec un README et une licence MIT, et le clone dans un dossier du même nom. Lancez la commande depuis le répertoire où vous rangez vos travaux de cours — hors des dossiers synchronisés au cloud comme Dropbox ou Google Drive.

(Pas de terminal ? L'équivalent navigateur est en [1.5](1.5_version_control_git.md#create-a-new-repository) ; clonez ensuite.)

**Vérifier :** ouvrez `https://github.com/YOURUSERNAME/MLGEO2026_UWNETID` dans un navigateur.

La réussite ressemble à ceci : la page du dépôt se charge et montre un README et un fichier LICENSE, et `ls MLGEO2026_UWNETID` sur votre machine montre les mêmes fichiers.

## Étape 4 — Cloner le livre du cours et installer son environnement

Clonez le dépôt du cours et laissez pixi construire l'environnement depuis le fichier de verrouillage :

    git clone https://github.com/geo-smart/mlgeo-book.git
    cd mlgeo-book
    pixi install

Le premier `pixi install` télécharge quelques gigaoctets de paquets ; comptez plusieurs minutes sur une connexion rapide. Lancez ensuite JupyterLab depuis l'environnement :

    pixi run jupyter lab

**Vérifier :** JupyterLab s'ouvre dans votre navigateur (ou affiche une URL `http://localhost:8888/lab?token=...` à ouvrir).

La réussite ressemble à ceci : l'interface JupyterLab se charge et son explorateur de fichiers montre le dossier `book/`. Arrêtez-la plus tard avec `Ctrl-C` dans le terminal.

```{tip}
`pixi run` utilise toujours l'environnement propre au projet — il n'y a pas d'environnement à activer ni à oublier. Si `pixi install` échoue en cours de route (aléa réseau), relancez-le ; il reprend.
```

## Étape 5 — Premier test : exécuter un carnet

Un **test de fumée** (*smoke test*) est une vérification courte et rapide que la mécanique de base fonctionne de bout en bout : les paquets s'importent, un petit calcul dont on connaît la réponse renvoie cette réponse, et une sortie apparaît. Le nom vient des essais de matériel électronique : on met l'appareil neuf sous tension et on vérifie que rien ne fume. Un test de fumée ne montre pas qu'un résultat scientifique est juste. Il montre que l'installation n'échoue pas d'emblée, en quelques secondes plutôt qu'au bout d'une heure de calcul réel. Lancez-le en premier sur toute nouvelle machine et après chaque modification de l'environnement. C'est aussi la première chose qu'une autre personne exécute pour savoir si votre dépôt fonctionne sur son ordinateur. Cette étape teste l'environnement du livre du cours ; l'étape 6 ajoute un test de fumée à votre propre dépôt.

Dans JupyterLab, ouvrez n'importe quel carnet du chapitre 1 — par exemple `book/Chapter1-GettingStarted/1.7_get_geodetic_gnss.ipynb` — et exécutez les premières cellules (`Shift-Entrée`).

La réussite ressemble à ceci : les cellules d'import s'exécutent sans `ModuleNotFoundError`, et la première cellule de données ou de tracé produit une sortie. Si les imports échouent, vous exécutez probablement un noyau hors de l'environnement pixi : vérifiez que vous avez lancé JupyterLab avec `pixi run jupyter lab` depuis le répertoire `mlgeo-book`.

## Étape 6 — Pousser une modification vers votre propre dépôt

Bouclez la boucle en poussant un *commit* vers `MLGEO2026_UWNETID`. Dans un terminal, allez dans votre dépôt de l'étape 3, éditez `README.md` (ajoutez une ligne de titre, votre nom, et une phrase sur ce que vous attendez de ce cours), puis :

    git add README.md
    git commit -m "Introduce myself in the README"
    git push

Pendant que vous y êtes, ajoutez l'environnement du cours à votre dépôt, pour que votre propre travail soit reproductible dès le premier jour. Le livre contient, dans son dossier `environments/student/`, un manifeste écrit pour les dépôts d'étudiants. Copiez-le avec son fichier de verrouillage à la racine de votre dépôt, puis installez :

    cp ../mlgeo-book/environments/student/pixi.toml ../mlgeo-book/environments/student/pixi.lock .
    pixi install

(Ajustez le chemin `../mlgeo-book/` si vos dossiers sont ailleurs.) Ne copiez pas à la place le `pixi.toml` situé à la racine du livre. Il installe le paquet `mlgeo_synth` du livre depuis le dossier du livre, qui n'existe pas dans votre dépôt : chaque `pixi run` y échoue alors avec « does not appear to be a Python project ». Ses tâches de construction supposent en outre les dossiers du livre. Le manifeste étudiant épingle les mêmes versions de paquets que le fichier de verrouillage du livre, installe `mlgeo_synth` depuis un instantané du livre sur GitHub, laisse de côté les outils qui construisent le livre et ajoute `pixi run lab` pour lancer JupyterLab dans votre dépôt. Comme pixi réutilise les paquets téléchargés à l'étape 4, cette installation prend une ou deux minutes au lieu de plusieurs.

Donnez maintenant à votre dépôt son propre test de fumée. Enregistrez ceci sous le nom `smoke_test.py` dans le dépôt :

```python
"""Smoke test: check that the course environment runs before doing real work."""
import platform

import numpy as np
import pandas as pd
import xarray as xr

# A calculation with a known answer: a line rising 2.5 mm/yr must give slope 2.5.
t = np.arange(0.0, 10.0, 0.1)
slope = np.polyfit(t, 2.5 * t + 1.0, 1)[0]
assert abs(slope - 2.5) < 1e-9, f"expected slope 2.5, got {slope}"

print(f"Python {platform.python_version()} on {platform.system()} {platform.machine()}")
print(f"numpy {np.__version__}, pandas {pd.__version__}, xarray {xr.__version__}")
print("smoke test passed")
```

Déclarez-le comme tâche pixi et lancez-le :

    pixi task add smoke "python smoke_test.py"
    pixi run smoke

La réussite ressemble à ceci : la dernière ligne affichée est `smoke test passed`. Ajoutez à `README.md` une section **How to run** qui nomme la commande (`pixi run smoke`) et indique le système d'exploitation et le type de machine donnés par la première ligne affichée, par exemple `Tested on Darwin arm64`. Puis validez et poussez :

    git add pixi.toml pixi.lock smoke_test.py README.md
    git commit -m "Add course environment and smoke test"
    git push

**Vérifier :** rechargez la page du dépôt sur GitHub.

La réussite ressemble à ceci : votre modification du README, les deux fichiers pixi et `smoke_test.py` sont visibles sur GitHub, et les *commits* apparaissent sous **Commits** avec votre nom d'utilisateur. En cours le mercredi 7 octobre, un ou une camarade clonera votre dépôt et lancera `pixi run smoke` avec votre seul README pour guide.

## Étape 7 — Écrire un AGENTS.md

Un fichier d'instructions indique à votre agent de programmation comment le travail se fait dans votre dépôt. La séance 3 en a tiré un de la grille d'évaluation de la classe ; donnez maintenant à `MLGEO2026_UWNETID` le sien. Créez `AGENTS.md` à la racine du dépôt avec au moins cinq règles, chacune étant une vérification que l'on peut trancher en lisant la sortie de l'agent ou vos *commits*. Partez de ce modèle et adaptez-le :

```markdown
# AGENTS.md for MLGEO2026_UWNETID
## Environment
- Run all code through `pixi run`; add packages only through pixi.toml.
- Run `pixi run smoke` before reporting any result.
## Data
- Fetch values that a provider publishes (station coordinates, velocities,
  catalogs) and cite the URL and retrieval date; do not recompute or retype them.
- Cite every dataset by DOI in the README.
## Reporting
- State the reference frame, units, and time window of every number.
- Mark AI-drafted commits: "AI-assisted: <tool>, <what it drafted>".
```

Une règle comme « écrire du code propre » ne peut pas être vérifiée et ne compte pas parmi les cinq. Claude Code lit `AGENTS.md` lorsque le dépôt ne contient pas de `CLAUDE.md` ; si vous gardez aussi un `CLAUDE.md`, ajoutez-y la ligne `@AGENTS.md` pour que les deux soient chargés. Le site [agents.md](https://agents.md/) liste les autres agents qui lisent ce fichier et la manière de les configurer.

    git add AGENTS.md
    git commit -m "Add agent instructions from the class rubric"
    git push

La réussite ressemble à ceci : `AGENTS.md` est visible sur GitHub avec au moins cinq règles vérifiables. Plus tard dans le trimestre, [6.3](../Chapter6-AgenticAI/6.3_build_an_eval_set.ipynb) transforme une spécification de ce type en jeu d'évaluation et mesure si un agent la respecte.
