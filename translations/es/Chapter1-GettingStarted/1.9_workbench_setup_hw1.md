Esta página es la Tarea 1. Lo guía por la instalación de las herramientas que usará todo el trimestre: pixi para los entornos, git y GitHub para el control de versiones, y JupyterLab para los cuadernos. Cada paso termina en un estado que usted puede verificar, así siempre sabe si funcionó antes de seguir. Presupueste una a dos horas; pida ayuda temprano si un paso falla.

Al final tendrá: pixi y git instalados, una cuenta de GitHub, su repositorio personal del curso `MLGEO2026_UWNETID` (reemplace `UWNETID` por su identificador — en la Universidad de Washington, el UW NetID), el libro del curso corriendo localmente y una confirmación empujada a su propio repositorio.

```{note}
**Usuarios de Windows: lean esto primero.** El entorno del curso (`pixi.toml`) apunta por ahora a macOS (Apple silicon) y Linux, no a Windows nativo. Tiene dos rutas oficiales:

* **WSL2 (principal).** Windows Subsystem for Linux le da un sistema Ubuntu completo dentro de Windows. Abra PowerShell como administrador, ejecute `wsl --install`, reinicie y abra la terminal de Ubuntu ([guía de instalación de Microsoft](https://learn.microsoft.com/en-us/windows/wsl/install)). Desde ahí, siga cada instrucción de Linux de esta página dentro de la terminal de Ubuntu. VS Code se conecta a WSL2 directamente con la [extensión WSL](https://code.visualstudio.com/docs/remote/wsl).
* **GitHub Codespaces (alternativa sin instalar nada).** Si WSL2 no es una opción (laptop bloqueada por su institución, poco disco), corra todo en el navegador: después del paso 2 (cuenta de GitHub), abra el repositorio del curso en GitHub, haga clic en **Code → Codespaces → Create codespace** y continúe desde el paso 4 en la terminal del *codespace*. Las cuentas personales incluyen una cuota mensual gratuita.
```

## Registros de IA: llévelos desde el primer paso

Cuando su repositorio exista (paso 3), cree una carpeta `AI_logs/` en su raíz. Para cada sesión, agregue un archivo Markdown llamado `AAAA-MM-DD_herramienta_tarea.md`, por ejemplo `2026-10-12_claude-code_agents-md.md`, con esta estructura (mantenga los títulos en inglés):

Use la exportación de la herramienta cuando exista (en Claude Code, `/export` guarda la conversación); si no, copie la conversación desde la ventana del chat. Luego agregue `AI_logs/README.md` con la tabla de declaración del curso, una fila por archivo de registro:

```markdown
| Log | Tool | Task | What I verified |

```

Su repositorio es público: lea cada registro antes de confirmarlo y quite tokens, contraseñas y datos personales. Una revisión rápida es `grep -n -i "token\|password\|ghp_" AI_logs/*.md`. Si no usó ninguna herramienta de IA fuera del paso 8, dígalo en `AI_logs/README.md`; un "ninguna" honesto obtiene los puntos.

## Paso 1 — Instale pixi

**macOS / Linux / WSL2**, en una terminal:

    curl -fsSL https://pixi.sh/install.sh | sh

En macOS con [Homebrew](https://brew.sh), `brew install pixi` también funciona. Después de instalar, cierre y reabra la terminal para que su *shell* tome el PATH nuevo.

**Verifique:**

    pixi --version

El éxito se ve así: se imprime un número de versión, por ejemplo `pixi 0.48.0`. Si el comando no se encuentra, reinicie la terminal; si sigue sin encontrarse, el instalador imprime la línea que hay que agregar al perfil de su *shell* — agréguela y reinicie otra vez.

## Paso 2 — Instale git y cree una cuenta de GitHub

Compruebe si git ya está instalado:

    git --version

Si no: en macOS, ejecutar ese comando dispara el instalador de las Xcode Command Line Tools (acéptelo); en Ubuntu/WSL2, `sudo apt install git`.

Luego:

1. Cree una cuenta en [github.com](https://github.com/) y configure la autenticación de dos factores (vea [1.5](1.5_version_control_git.md#authentication)).
2. Dígale a git quién es usted, con el mismo nombre de usuario y correo que la cuenta de GitHub:

       git config --global user.name "superseismo"
       git config --global user.email "superseismo@uw.edu"

3. Instale la [GitHub CLI](https://cli.github.com/) y autentíquese:

       gh auth login

   Acepte los valores por defecto (GitHub.com, HTTPS, iniciar sesión con un navegador web) y siga las indicaciones del navegador.

**Verifique:**

    git --version
    gh auth status

El éxito se ve así: git imprime una versión 2.40 o más nueva, y `gh auth status` reporta `Logged in to github.com` con su nombre de usuario.

## Paso 3 — Cree su repositorio del curso

Cree su repositorio personal del curso, llamado `MLGEO2026_UWNETID` (su identificador en mayúsculas, por ejemplo `MLGEO2026_SUPERSEISMO`). Este repositorio guarda sus tareas y su trabajo de proyecto durante el trimestre. Créelo **una sola vez**, con un comando:

    gh repo create MLGEO2026_UWNETID --public --add-readme --license mit --clone

Esto crea el repositorio en GitHub con un README y una licencia MIT, y lo clona en una carpeta del mismo nombre. Ejecútelo desde el directorio donde guarda el trabajo del curso — fuera de carpetas sincronizadas con la nube como Dropbox o Google Drive.

(¿Sin terminal? El equivalente en el navegador está en [1.5](1.5_version_control_git.md#create-a-new-repository); luego clónelo.)

**Verifique:** abra `https://github.com/SU-USUARIO/MLGEO2026_UWNETID` en un navegador (con su nombre de usuario de GitHub).

El éxito se ve así: la página del repositorio carga y muestra un README y un archivo LICENSE, y `ls MLGEO2026_UWNETID` en su computadora muestra los mismos archivos.

## Paso 4 — Clone el libro del curso e instale su entorno

Clone el repositorio del curso y deje que pixi construya el entorno desde el archivo de bloqueo:

    git clone https://github.com/geo-smart/mlgeo-book.git
    cd mlgeo-book
    pixi install

El primer `pixi install` descarga unos cuantos gigabytes de paquetes; espere varios minutos con una conexión rápida — y más con una lenta: si su conexión es inestable, simplemente reejecute el comando cuando se corte. Luego lance JupyterLab desde dentro del entorno:

    pixi run jupyter lab

**Verifique:** JupyterLab se abre en su navegador (o imprime una URL `http://localhost:8888/lab?token=...` para abrir).

El éxito se ve así: la interfaz de JupyterLab carga y su navegador de archivos muestra la carpeta `book/`. Deténgalo más tarde con `Ctrl-C` en la terminal.

```{tip}
`pixi run` siempre usa el entorno propio del proyecto — no hay entorno que activar ni que olvidar. Si `pixi install` falla a medio camino (un corte de red), ejecútelo otra vez; retoma donde iba.
```

## Paso 5 — Prueba de humo: ejecute un cuaderno

Una **prueba de humo** (*smoke test*) es una verificación corta y rápida de que la maquinaria básica funciona de principio a fin: los paquetes se importan, un cálculo pequeño con respuesta conocida devuelve esa respuesta, y aparece una salida. El nombre viene de las pruebas de hardware: se enciende el aparato nuevo y se comprueba que nada eche humo. Una prueba de humo no demuestra que un resultado científico sea correcto. Demuestra que la instalación no falla de entrada, en segundos y no después de una hora de cálculo real. Córrala primero en cualquier máquina nueva y después de cada cambio del entorno. También es lo primero que otra persona ejecuta para saber si su repositorio funciona en su computadora. Este paso prueba el entorno del libro del curso; el paso 6 agrega una prueba de humo a su propio repositorio.

En JupyterLab, abra cualquier cuaderno del capítulo 1 — por ejemplo `book/Chapter1-GettingStarted/1.7_get_geodetic_gnss.ipynb` — y ejecute las primeras celdas (`Shift-Enter`).

El éxito se ve así: las celdas de importación terminan sin `ModuleNotFoundError`, y la primera celda de datos o de gráfica produce salida. Si las importaciones fallan, probablemente está corriendo un kernel fuera del entorno pixi: compruebe que lanzó JupyterLab con `pixi run jupyter lab` desde el directorio `mlgeo-book`.

## Paso 6 — Empuje un cambio a su propio repositorio

Cierre el círculo empujando una confirmación a `MLGEO2026_UWNETID`. En una terminal, vaya a su repositorio del paso 3, edite `README.md` (agregue una línea de título, su nombre y una oración sobre lo que quiere obtener de este curso), y luego:

    git add README.md
    git commit -m "Introduce myself in the README"
    git push

Ya que está en eso, agregue el entorno del curso a su repositorio, para que su propio trabajo sea reproducible desde el primer día. El libro guarda, en su carpeta `environments/student/`, un manifiesto escrito para repositorios de estudiantes. Copie ese archivo y su archivo de bloqueo a la raíz de su repositorio, e instale:

    cp ../mlgeo-book/environments/student/pixi.toml ../mlgeo-book/environments/student/pixi.lock .
    pixi install

(Ajuste la ruta `../mlgeo-book/` si sus carpetas viven en otro lado.) No copie en su lugar el `pixi.toml` de la raíz del libro. Ese archivo instala el paquete `mlgeo_synth` del libro desde la carpeta del libro, que no existe en su repositorio, así que cada `pixi run` allí falla con «does not appear to be a Python project»; además, sus tareas de compilación esperan las carpetas del libro. El manifiesto para estudiantes fija las mismas versiones de paquetes que el archivo de bloqueo del libro, instala `mlgeo_synth` desde una instantánea del libro en GitHub, deja fuera las herramientas que compilan el libro y agrega `pixi run lab` para abrir JupyterLab en su repositorio. Como pixi reutiliza los paquetes que descargó en el paso 4, esta instalación tarda uno o dos minutos y no varios.

Ahora dele a su repositorio su propia prueba de humo. Guarde esto como `smoke_test.py` en el repositorio:

```python
"""Smoke test: check that the course environment runs before doing real work."""
import platform

import numpy as np
import pandas as pd
import xarray as xr

# A calculation with a known answer: a line rising 2.5 mm/yr must give slope 2.5.
t = np.arange(0.0, 10.0, 0.1)
slope = np.polyfit(t, 2.5 * t + 1.0, 1)[0]
assert abs(slope - 2.5) < 1e-9, f"expected slope 2.5, got {slope}"

print(f"Python {platform.python_version()} on {platform.system()} {platform.machine()}")
print(f"numpy {np.__version__}, pandas {pd.__version__}, xarray {xr.__version__}")
print("smoke test passed")
```

Regístrela como tarea de pixi y córrala:

    pixi task add smoke "python smoke_test.py"
    pixi run smoke

El éxito se ve así: la última línea impresa es `smoke test passed`. Agregue a `README.md` una sección **How to run** que nombre el comando (`pixi run smoke`) y registre el sistema operativo y el tipo de máquina de la primera línea impresa, por ejemplo `Tested on Darwin arm64`. Luego confirme y empuje:

    git add pixi.toml pixi.lock smoke_test.py README.md
    git commit -m "Add course environment and smoke test"
    git push

**Verifique:** recargue la página del repositorio en GitHub.

El éxito se ve así: su edición del README, los dos archivos pixi y `smoke_test.py` son visibles en GitHub, y las confirmaciones aparecen bajo **Commits** con su nombre de usuario. En clase, el miércoles 7 de octubre, un compañero o compañera clonará su repositorio y correrá `pixi run smoke` guiándose solo por su README.

## Paso 7 — Escriba un AGENTS.md

Un archivo de instrucciones le indica a su agente de programación cómo se trabaja en su repositorio. La sesión 3 derivó uno de la rúbrica de la clase; ahora dele a `MLGEO2026_UWNETID` el suyo. Cree `AGENTS.md` en la raíz del repositorio con al menos cinco reglas, cada una una verificación que alguien pueda resolver leyendo la salida del agente o sus confirmaciones. Parta de esta plantilla y adáptela:

```markdown
# AGENTS.md for MLGEO2026_UWNETID

## Project
Course repository for ESS 469/569, Autumn 2026: homeworks and the final project.
Every number and figure here must be regenerated from a fresh clone using
the commands in README.md.

## Environment and compute
- Run all code through `pixi run`; add packages only with `pixi add`, and
  commit pixi.toml and pixi.lock together.
- Do not install packages with pip or conda outside pixi.

## Data and provenance
- Fetch values that a provider publishes (station coordinates, velocities,
  catalogs) and cite the URL and retrieval date; do not recompute or retype them.
- Download data with a script in this repository, not by hand, and record the
  dataset DOI or URL, version, and retrieval date in README.md.
- Never modify raw data files; write processed data to a separate folder.

## Code and workflow
- Use paths relative to the repository root; no absolute paths such as /Users/...
- Every notebook must run top to bottom after Restart Kernel and Run All Cells.
- Every reported number and figure comes from a command listed in README.md.

## Reporting and credit
- State the reference frame, units, and time window of every number.
- Mark AI-drafted commits: "AI-assisted: <tool>, <what it drafted>".

## Verification
- Run `pixi run smoke` before reporting any result, and show its last line.
- Report the exact commands you ran and the commit hash they ran on.
- If a check fails or a value cannot be fetched, say so; do not substitute an estimate.
```

Una regla como «escriba código limpio» no se puede verificar y no cuenta entre las cinco. Claude Code lee `AGENTS.md` cuando el repositorio no tiene `CLAUDE.md`; si además mantiene un `CLAUDE.md`, agréguele la línea `@AGENTS.md` para que se carguen ambos. El sitio [agents.md](https://agents.md/) enumera los demás agentes que leen este archivo y cómo configurarlos.

    git add AGENTS.md
    git commit -m "Add agent instructions from the class rubric"
    git push

El éxito se ve así: `AGENTS.md` es visible en GitHub con al menos cinco reglas verificables. Más adelante en el trimestre, [6.3](../Chapter6-AgenticAI/6.3_build_an_eval_set.ipynb) convierte una especificación como esta en un conjunto de evaluación y mide si un agente la cumple.
